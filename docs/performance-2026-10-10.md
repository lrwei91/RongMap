# 2026-10-10 性能优化记录

核验时间：2026-10-10 01:12（Asia/Shanghai）；基线提交 `05873da`。以下都是本地构建和 Chromium 的结果，不代表生产网速或手机上的真实帧率。

## 改动

- 行程、管理、登录和公开分享页面改为按路由加载，原有业务流程和加载提示都保留。
- 地图标记只在内容、坐标、层级或名称变化时调用 SDK。点击事件读取最新的回调和地点数据，父组件回调变动不会再触发全部标记刷新。
- 地图复用已定位的地点集合；空路线参数保持稳定，无关渲染不会触发路线清理。
- 行程编辑页和分享页缓存路线与标记数据；编辑页同时缓存候选地点和草稿序列化结果，发现页缓存已收藏的 ID 集合。
- 移除 App 里重复的地点标准化，改由 `loadBootstrap` 统一处理。

## 前后对比

同一依赖环境下跑 Vite 生产构建，主入口 JavaScript 的大小（十进制 kB）：

| 指标 | 基线 | 优化后 |
| --- | ---: | ---: |
| 主入口大小 | 508.42 kB | 470.36 kB |
| gzip 大小 | 148.44 kB | 138.00 kB |

主入口减少约 7.5%，gzip 减少约 7.0%。延后加载的页面仍然需要下载，首次打开这些页面会有分包请求；这里没有说全部资源的总大小都减少了。

千地点地图测试统计了 `setContent`、`setPosition`、`setzIndex` 的调用次数：

| 操作 | 基线 | 优化后 |
| --- | ---: | ---: |
| 勾选一个列表地点 | 1000 / 1000 / 1000 | 0 / 0 / 0 |
| 激活一个地图地点（单次） | 1000 / 1000 / 1000 | 1 / 0 / 1 |

同一天在公开行程里切换地点会复用已有路线；切换日期仍会更新路线高亮。回归断言见 `tests/e2e/map-performance.spec.js`。标记的首次创建仍与地点数量成正比，这一轮没有做聚合或视口裁剪。
